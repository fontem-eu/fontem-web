Decisions Made (from review)

  • Standardize on ISO alpha-3 country codes (FRA, DEU, not FR, DE). Alpha-3 is more readable and matches TED. Migrate all 3.26M GLEIF nodes from alpha-2 → alpha-3 using pycountry.
  • Keep ticker: str in the FinancialDataSource interface. Resolution from gmr_id → ticker happens at the API router level via resolve_company_id(). The interface stays clean.
  • Remove RoutingDataSource + EsefDataSource + LiveDataSource dead code. Dead code is dead code.
  • Admin URLs: break old links, no redirects. Dev environment, safe to change.
  • Dedup strategy: normalize first, defer conflicts. Fix country codes, auto-merge only when no property conflicts. Conflicting fields (different VATs, different names) go to SAME_AS queue for manual review.
  • Coverage matrix: E2E tests only. 75 tests across 4 files — manageable scope. No decorator/annotation system for unit tests. Simple requirements.yml + mapping file.
  • Plan + requirements visible in admin area.

C1: Country Code Standardization + Dedup

C1 Standardize on ISO alpha-3 + clean up duplicates

Step 1: Add pycountry dependency

Add to Requirements.txt. Use pycountry.countries.get(alpha_2=code).alpha_3 for normalization. Covers all 249 ISO countries (not just EU).

Step 2: Migration script — src/etl/normalize_countries.py

Batch-update all Company, Authority, and Contract nodes with alpha-2 codes to alpha-3:

MATCH (c:Company) WHERE size(c.country) = 2
WITH c, pycountry_lookup(c.country) AS alpha3
SET c.country = alpha3

This affects 3.26M GLEIF nodes + ~17K Listings. Run once. Idempotent (alpha-3 codes stay alpha-3).

Step 3: Fix ETL pipelines

  • load_gleif.py: convert GLEIF alpha-2 to alpha-3 before MERGE
  • load_eu_listings.py: normalize COUNTRY_CURRENCY map keys to alpha-3
  • load_us_companies.py: set country = "USA" instead of "US"
  • ted_matcher.py: already uses alpha-3 (TED native) — no change needed
  • load_fr_directors.py: normalize country before matching

Step 4: Dedup script — src/etl/dedup_companies.py

  1. Find exact-name + exact-country pairs where one has LEI and the other doesn’t
  2. Auto-merge if no property conflicts (all shared non-null fields are identical)
  3. Create [:SAME_AS] if any field conflicts (different VATs, different names). These go to the operator review queue.
  4. Create :MergeEvent audit nodes for every auto-merge
  5. Log stats: merged count, deferred count, conflict details
SOCOMEC example: After normalization, we’ll have 4 SOCOMEC/FRA nodes. The GLEIF one (with LEI) is canonical. The 3 TED ones have different VATs (0, 1481141-1-0-1, 54850014900339). Since VAT conflicts, these go to SAME_AS — not auto-merged. An operator reviews and picks the real VAT.

C7: Corporate Group Structure (GLEIF Level 2)

C7 Parent-subsidiary relationships + group view

The problem

Mota-Engil has 19 entities in the graph — subsidiaries across Portugal, Poland, Czech Republic, Mexico, Netherlands, Africa. They’re all related (MOTA-ENGIL SGPS S.A. is the holding company) but the graph treats them as disconnected. A user searching for “Mota-Engil” sees 19 separate results with no indication they’re the same group.

Data source: GLEIF Level 2 (Relationship Records)

Available as a daily bulk download, same approach as Level 1:

  • 640,836 relationship records
  • Format: ZIP containing XML (same as Level 1)
  • URL: https://leidata.gleif.org/api/v1/concatenated-files/rr/get/{id}/zip
  • Fields: child LEI, parent LEI, relationship type (direct/ultimate), status (active/inactive)
  • 93.5% of our 3.45M companies have LEIs — high match rate expected
Verified: GLEIF API confirms MOTA-ENGIL SGPS S.A. (LEI: 549300L6RR1203WN9F57) is the direct parent of 7 subsidiaries. The Level 2 bulk file has this data for 640K+ relationships globally.

Neo4j data model

(:Company)-[:SUBSIDIARY_OF {type: "direct"}]->(:Company)
(:Company)-[:SUBSIDIARY_OF {type: "ultimate"}]->(:Company)

// Example: Mota-Engil Latin America B.V. -[:SUBSIDIARY_OF]-> Mota-Engil SGPS S.A.

ETL: src/etl/load_gleif_relationships.py

Same pattern as load_gleif.py:

  1. Download Level 2 ZIP (~50–100 MB)
  2. Stream-parse XML with iterparse
  3. For each relationship: look up both LEIs, create [:SUBSIDIARY_OF]
  4. Batch MERGE, idempotent, safe to re-run weekly

API

EndpointPurpose
GET /companies/{gmr_id}/groupReturn the corporate group tree (parent + all subsidiaries)
GET /companies/{gmr_id}/group/contractsAggregate contracts across the entire group
// Cypher: get entire group from any member
MATCH (member:Company {gmr_id: $gid})
OPTIONAL MATCH (member)-[:SUBSIDIARY_OF*0..5]->(parent)
WHERE NOT (parent)-[:SUBSIDIARY_OF]->()  // ultimate parent
WITH COALESCE(parent, member) AS root
MATCH (root)<-[:SUBSIDIARY_OF*0..5]-(child)
RETURN root, collect(DISTINCT child) AS subsidiaries

UI: Corporate Group section in company profile

  • Group header: “Part of MOTA-ENGIL SGPS S.A. group (19 entities, 7 countries)”
  • Collapsible tree: ultimate parent at top, children indented. Each node: name, country, contract count. Clickable to navigate. Collapsed by default if >10 children at any level.
  • Group aggregate: “Group total: 36 contracts, €X total value” — toggle to see contracts for the whole group vs just this entity
  • Search grouping: when searching, subsidiaries are grouped under the parent entity — one result for the group, showing entity count and aggregate contract value

Traversal: levels, not shortcuts

Use [:SUBSIDIARY_OF*0..5] for full level-by-level traversal. Slower but preserves all intermediate structure. We can always add an ultimate-parent shortcut later for performance if needed.

Dependency on C1

C7 should run after C1 (country normalization). The Level 2 loader uses LEI matching, not country codes, so it doesn’t directly depend on C1. But the group view in the UI will show country codes, so those should be normalized first.

Decisions Log (from review)

Q1 → Use levels. [:SUBSIDIARY_OF*0..5] traversal. Slower but preserves all data. Can compress to ultimate-parent shortcut later if performance requires it.
Q2 → Collapsible tree. Default to collapsed if >10 children at any level. Full tree visible on expand. Works on mobile (nodes are clickable links, not a D3 visualization).
Q3 → Yes, group in search. Subsidiaries shown as one grouped result under the parent entity. Shows entity count + aggregate contracts.
Q4 → Never change a primary key. gmr_id stays untouched. Only the display country property is normalized. Future ETL runs will use alpha-3 in gmr_id.from_name(), so new companies get alpha-3-based IDs. Existing name-based IDs with alpha-2 remain valid — they’re deterministic and stable.
Q5 → Adapt valuable tests, delete the rest. After investigation:
  • test_routing_data_source.py (14 tests): Delete — pure routing logic that no longer exists.
  • test_esef_data_source.py (29 tests): Adapt ~6 contract tests (all keys present, sorted descending, shares_outstanding derivation) to GraphDataSource. Delete the 23 ESEF-specific tests.
  • test_api_eu_tickers.py (23 tests): Adapt all — these test the API contract with EU data, valuable regardless of backend.
  • test_ticker_functionality.py (11 tests): Adapt all — search behavior tests (exact match, case insensitive, limit).

Net result: delete ~37 tests, adapt ~40 tests, keep ~500 unchanged.
