Decisions Made (from review)

  • Standardize on ISO alpha-3 country codes (FRA, DEU, not FR, DE). Alpha-3 is more readable and matches TED. Migrate all 3.26M GLEIF nodes from alpha-2 → alpha-3 using pycountry.
  • Keep ticker: str in the FinancialDataSource interface. Resolution from gmr_id → ticker happens at the API router level via resolve_company_id(). The interface stays clean.
  • Remove RoutingDataSource + EsefDataSource + LiveDataSource dead code. Dead code is dead code.
  • Admin URLs: break old links, no redirects. Dev environment, safe to change.
  • Dedup strategy: normalize first, defer conflicts. Fix country codes, auto-merge only when no property conflicts. Conflicting fields (different VATs, different names) go to SAME_AS queue for manual review.
  • Coverage matrix: E2E tests only. 75 tests across 4 files — manageable scope. No decorator/annotation system for unit tests. Simple requirements.yml + mapping file.
  • Plan + requirements visible in admin area.

C1: Country Code Standardization + Dedup

C1 Standardize on ISO alpha-3 + clean up duplicates

Step 1: Add pycountry dependency

Add to Requirements.txt. Use pycountry.countries.get(alpha_2=code).alpha_3 for normalization. Covers all 249 ISO countries (not just EU).

Step 2: Migration script — src/etl/normalize_countries.py

Batch-update all Company, Authority, and Contract nodes with alpha-2 codes to alpha-3:

MATCH (c:Company) WHERE size(c.country) = 2
WITH c, pycountry_lookup(c.country) AS alpha3
SET c.country = alpha3

This affects 3.26M GLEIF nodes + ~17K Listings. Run once. Idempotent (alpha-3 codes stay alpha-3).

Step 3: Fix ETL pipelines

  • load_gleif.py: convert GLEIF alpha-2 to alpha-3 before MERGE
  • load_eu_listings.py: normalize COUNTRY_CURRENCY map keys to alpha-3
  • load_us_companies.py: set country = "USA" instead of "US"
  • ted_matcher.py: already uses alpha-3 (TED native) — no change needed
  • load_fr_directors.py: normalize country before matching

Step 4: Dedup script — src/etl/dedup_companies.py

  1. Find exact-name + exact-country pairs where one has LEI and the other doesn’t
  2. Auto-merge if no property conflicts (all shared non-null fields are identical)
  3. Create [:SAME_AS] if any field conflicts (different VATs, different names). These go to the operator review queue.
  4. Create :MergeEvent audit nodes for every auto-merge
  5. Log stats: merged count, deferred count, conflict details
SOCOMEC example: After normalization, we’ll have 4 SOCOMEC/FRA nodes. The GLEIF one (with LEI) is canonical. The 3 TED ones have different VATs (0, 1481141-1-0-1, 54850014900339). Since VAT conflicts, these go to SAME_AS — not auto-merged. An operator reviews and picks the real VAT.

C6: E2E Coverage Matrix

C6 Requirements × E2E test traceability

Scope: E2E tests only (75 tests, 4 files)

No decorators, no unit test annotations. A simple requirements.yml file + a mapping file that links e2e test names to requirement IDs.

Implementation

  1. requirements.yml in the repo root: list of requirements with IDs, titles, categories
  2. coverage-map.yml: maps {test_file}::{test_name} → [REQ-001, REQ-002]
  3. A Python script (scripts/coverage_matrix.py) that parses both files, cross-references with actual test names from Playwright output, generates a JSON matrix
  4. API endpoint: GET /api/admin/coverage serves the matrix JSON (or static file)
  5. Admin page: /admin/coverage renders the matrix as a table (green = covered, red = uncovered)

Requirements page: /admin/requirements

Renders requirements.yml as a browsable list grouped by category. Each requirement shows: ID, title, status (covered / uncovered), linked test names.
