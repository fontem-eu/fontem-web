What’s been built: Neo4j graph with GLEIF companies, ESEF+EDGAR financials, TED procurement contracts, French company directors. GraphDataSource serving production. Unified search, company profile, contracts tab, data quality dashboard, entity resolution page, PWA.

Problems Identified

1. Country code mismatch → 190K duplicate Company nodes.

GLEIF uses ISO alpha-2 (FR, DE, ES). TED uses ISO alpha-3 (FRA, DEU, ESP). The ETL creates new Company nodes for TED contractors because country = "FRA" doesn’t match country = "FR" on existing GLEIF nodes. This is the #1 data quality issue.

Example: SOCOMEC has two nodes — one from GLEIF (FR, has LEI) and one from TED (FRA, no LEI, vat=0). Identical company, two gmr_ids.

2. ticker is still a first-class citizen in the backend.

7 API route paths use /{ticker}/. 9 handler functions take ticker: str. 70+ references in the frontend. The FinancialDataSource interface takes ticker as the primary key for every method. This should be gmr_id.

3. No admin area.

The entity resolution page and data quality dashboard exist but aren’t grouped. No architecture documentation is visible. No way to trigger deduplication or review system health in one place.

4. Landing page is outdated.

Still talks about “10,000+ US-listed companies” and SEC EDGAR. Doesn’t mention procurement, directors, or the knowledge graph. Features list doesn’t reflect current capabilities.

C1: Country Code Normalization + Deduplication Script

C1 Fix the root cause, then clean up

Root cause fix: normalize country codes at ETL time

Add an alpha-3 → alpha-2 mapping to ted_matcher.py and load_ted_contracts.py. Every TED country code is converted before matching or node creation. ~30 entries covering EU+EFTA.

Deduplication script: src/etl/dedup_companies.py

A batch job that:

  1. Phase 1: Normalize all existing alpha-3 country codes to alpha-2 on Company nodes
  2. Phase 2: Find exact-name + country duplicates where one node has LEI and the other doesn’t
  3. Phase 3: Auto-merge trivial cases (same name, same country, no property conflicts)
  4. Phase 4: Create [:SAME_AS] for non-trivial cases (different names, both have data)

Idempotent, safe to re-run. Creates :MergeEvent audit nodes for every merge. Logs stats for the data quality dashboard.

Prevention: ted_matcher.py update

All future ETL runs normalize country codes before matching. The dedup script only needs to run once for historical data.

C2: Ticker → gmr_id Migration (Backend)

C2 Make gmr_id the primary key across the API

Strategy: dual-path endpoints, not a hard cutover

Every existing /{ticker}/fundamentals endpoint continues working. But internally, the first thing it does is resolve ticker → gmr_id (which resolve_company_id() already does). New endpoints are gmr_id-first from the start.

Interface evolution

The FinancialDataSource interface currently takes ticker: str as the key for every method. Phase C2 adds overloaded resolution: if the string is a UUID, it’s treated as a gmr_id; otherwise as a ticker. This is already partially done in get_annual_fundamentals() — extend to all methods.

Scope

FileChange
GraphDataSource (all methods)Accept both ticker and gmr_id via UUID detection
fundamentals.py, valuation.py, gmr.py, prices.pyAlready use resolve_company_id() — verify consistency
FinancialDataSource ABCDocument that ticker param accepts gmr_id too
Frontend API callsPass gmr_id when available, ticker as fallback

C4: Architecture Visualization

C4 Interactive architecture diagrams with Mermaid.js

Technology: Mermaid.js

Why Mermaid: renders diagrams from text markup in the browser via a single JS import. No build step, no server-side rendering, no dependencies beyond a CDN script tag. Diagrams are version-controlled as text (not binary images). Supports: flowcharts, class diagrams, ER diagrams, sequence diagrams. Dark/light theme built-in.

Diagrams to include

  • System overview: gmr-web → edgar-gmr-etl → Neo4j / NFS. Shows all k8s deployments, services, PVCs.
  • Data flow: GLEIF → load_gleif → Neo4j, TED → eforms-parser → load_ted → Neo4j, recherche-entreprises → load_fr_directors → Neo4j, etc.
  • Interface map: FinancialDataSource, ContractDataSource, PersonDataSource, EntityResolver, DataQualitySource — who implements what, who depends on what.
  • Neo4j schema: ER diagram of Company, Listing, FinancialYear, Contract, Authority, Person, CPV and their relationships.
  • ETL pipeline: sequence diagram of a TED contract load (download → parse → match → MERGE).

Implementation

A single Vue page at /admin/architecture that imports Mermaid from CDN and renders the diagrams from inline text blocks. Each diagram is a collapsible section. Mobile-responsive (diagrams scroll horizontally).

C6: Coverage Matrix Library

C6 Traceability from requirements to tests

Concept

A standalone library (coverage-matrix, separate git repo like eforms-parser) that:

  1. Defines requirements as a YAML/JSON file with IDs and descriptions
  2. Provides a Python decorator @covers("REQ-042") and a JS annotation // @covers REQ-042 for test functions
  3. Scans test files, extracts coverage annotations, and generates a matrix: requirement × test
  4. Outputs: JSON (for API), HTML (for admin page), or Markdown

Example

# requirements.yml
REQ-001:
  title: "Company search returns results from all sources"
  category: search
REQ-002:
  title: "Contracts tab shows procurement data for EU companies"
  category: procurement

# In test files:
@covers("REQ-001")
def test_unified_search_returns_companies_and_authorities():
    ...

// In Vue test files:
// @covers REQ-002
it('shows contracts when API returns data', async () => { ... })

Admin page: /admin/coverage

Displays the matrix as a table: green cells = covered, red = uncovered, grey = partially. Links to test source files. Auto-generated on each build.

Implementation scope

New repo: /config/repos/coverage-matrix/. Python package with CLI: coverage-matrix scan --tests tests/ --reqs requirements.yml --output matrix.json. The admin page fetches /api/coverage-matrix (or a static JSON file built at deploy time).
